THINGS HAPPENING ON EVERY TICK
==============================
A complete inventory of the work the game does per simulation tick and per
render frame, with file:line references, for finding performance issues.
Generated 2026-08-21 from the code as of this date; verify line numbers
against HEAD before acting on them.

Shape of the loop: there is NO monolithic Rust tick function. The Rust crate
exposes ~370 #[wasm_bindgen] kernels across 30 files; TICK ORDER IS OWNED BY
TYPESCRIPT, which calls Rust kernels phase by phase. Phase timing lives in
SIM_TICK_INSTRUMENTATION (src/game/perf/SimTickInstrumentation.ts:24) and
WASM_BOUNDARY_INSTRUMENTATION (src/game/perf/WasmBoundaryInstrumentation.ts:11),
both disabled by default.

Cadences (src/architecture.json): fixedStepHz 20 (50ms tick),
inputDelayTicks 15, checksumIntervalTicks 180, presentation snapshots
nominal 5 Hz.


1. TICK DRIVERS (who calls the sim)
-----------------------------------
A. Sandbox/demo/background: ServerTickLoop setInterval at tickRateHz
   (src/game/server/ServerTickLoop.ts:61-107). Accumulator with
   MAX_CATCH_UP_WINDOW_MS=25, 1..24 catch-up steps.
   Per interval (src/game/server/GameServer.ts:344-383):
   - startup-clients-ready gate
   - tick(delta) -> core.stepFixedTick
   - snapshot interval check -> queuePresentationSnapshot() via setTimeout(0)
     OR projectile-delta snapshot if pending events
   - recordTickWork / recordTickCadence EMAs

B. Real battle (lockstep): setInterval(pumpFrame, 50ms)
   (src/components/gameCanvasRealBattleStartup.ts:1765). GameServer's own
   loop is NOT running; it only publishes presentation snapshots.
   Per pump (gameCanvasRealBattleStartup.ts:1627-1722):
   - broadcastPeerFrameReport (throttled to 500ms)
   - scheduler.getDiagnostics() [allocates, incl. sorted queued-frame
     summaries; called twice per pump: 1637 and 1696]
   - coordinator only: command-frame budget, LockstepFlowControl.report
     (walks all seats), mint + archive + broadcast command frames
   - scheduler.advanceReadyFrames (cap 300/pump): per frame ->
     materializeCommandFrame, core.stepFixedTick, recent-frame trim,
     checksum every 180 frames (LockstepFrameScheduler.ts:296-304)
   - presentation snapshot gate (200ms) else projectile-delta snapshot
   - resendCommandFramesToLaggingPeers (throttled 250ms, <=300 frames)
   - requestMissingCommandFrameIfNeeded, pumpHistoryStreams

7. SNAPSHOT / NETWORK CADENCE
------------------------------
Per tick: snapshot-dirty marking (many sites); projectile motion event
coalescing; Rust presentation history capture.

Per pump (50ms, lockstep): see 1B. Acks are message-driven, not per-pump
(sendAck on each received command frame, NetworkLockstepTransport.ts:198).

Per presentation snapshot (nominal 200ms), ServerSnapshotPublisher.emit
(src/game/server/ServerSnapshotPublisher.ts:380-629):
  drainSimulationFrame (audio/sim events drain HERE, not per tick);
  lifecycle drain; buildServerMeta; clear per-team caches; per listener:
  visibility build (team-mask memoized; admin/spectator never cached),
  direct wire preencode (entity rows, supplementals, projectile rows,
  Rust wire encode) or fallback DTO path; shared global snapshot reuse
  for player-less listeners.
Projectile-only delta snapshots fire on pumps between presentation
snapshots when projectile lifecycle/beam topology changed
(GameServer.ts:328-338).

9. SCHEDULED PER-N (quick table)
---------------------------------
SIM: checksum 180 ticks; A* one ally team per tick, 4096 expansions;
refresh-lane preference every 8 turns; chase repath cooldown 7 ticks;
partial-plan retry 60 ticks; targeting reacquire probe 16 ticks
(entity-staggered); LOS drop grace 4 ticks; Rust fallback-LOS budget
12/batch; idle-builder scan 1s; reclaim blacklist 60s; laser/shield
sound refresh 2s; stuck-replan settle 2s; surface-lift probes bucketed
tick%bucketCount; beam pulse collision sampling interval (config.ts:191);
physics sphere iterations by body-count tier.
RENDER: HUD stride 1-4; effect stride 1-4; LOD rebuild 24u/8b per frame;
minimap 50ms scaled; economy UI 100ms; pixel ratio 750ms; presentation
snapshot 200ms; peer frame report 500ms; resend throttle 250ms; catch-up
replay budget 12ms per pump.

NOT per tick (common misconception): audio/sim event queues drain only
on snapshot emit (ServerSnapshotPublisher.ts:178-189); checksums only
every 180 frames; replay recording only on accepted commands.
